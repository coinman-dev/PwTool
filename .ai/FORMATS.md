# Форматы и алгоритмы, которые обязаны совпадать с оригиналом

Выписано из исходников Password Tech 3.6.1. Источник истины — код в `upstream/`; здесь краткая выжимка со ссылками, чтобы не выводить это заново. Все многобайтовые числа — little-endian, структуры упакованы без выравнивания.

Общее правило про строки: в Windows `wchar_t` — 16 бит, и во многих местах оригинал берёт байты строки как UTF-16LE. В порте это нужно воспроизводить явно; где именно — указано ниже.

## 1. База паролей `.pwdb`

Код: `upstream/src/passw/PasswDatabase.cpp` — структуры в строках 62–93, чтение 531–923, запись 979–1268.

### 1.1. Открытый заголовок файла (18 байт)

| Поле | Размер | Значение |
|---|---|---|
| Magic | 4 | `0x62645750`, в файле байты `P W d b` |
| HeaderSize | 1 | 18 |
| Version | 2 | `0x0108` для версии 1.8 |
| Flags | 4 | 1 — есть пароль восстановления; 2 — пароли в UTF-8 |
| CipherType | 1 | 0 — AES-256-CBC; 1 — ChaCha20 |
| HashType | 1 | 0 — SHA-256; 1 — SHA-512 (порт пишет 1) |
| KdfType | 1 | 0 — PBKDF2-HMAC-SHA256 |
| KdfIterations | 4 | по умолчанию 300 000 |

Ограничения: файл не больше 100 МБ; версия не ниже `0x0100`.

### 1.2. Остальной файл (версия 1.8)

```
[блок восстановления, 128 байт — только если установлен флаг 1]
соль, 32 байта
IV: 16 байт для AES, 8 байт для ChaCha20
шифртекст
HMAC: 64 байта (SHA-512) или 32 байта (SHA-256)
```

Блок восстановления — две ячейки по 64 байта: соль (32) и зашифрованный мастер-ключ (32). Первая ячейка открывается мастер-паролем, вторая — паролем восстановления.

### 1.3. Ключи

1. Байты ключа: пароль в UTF-8 (флаг 2) или в UTF-16LE (старые базы); если задан ключевой файл, к ним дописываются 32 байта ключа из файла (раздел 3). При смене мастер-пароля база переводится на UTF-8, кроме случая, когда установлен пароль восстановления, а база была в UTF-16 (`PasswManager.cpp:2566`).
2. `derived = PBKDF2-HMAC-SHA256(ключ, соль, KdfIterations, 32 байта)`.
3. Без пароля восстановления: `keySrc = derived`, соль — общая соль файла.
4. С паролем восстановления: для ячейки берётся её соль; мастер-ключ расшифровывается шифром базы с ключом `derived` и IV, равным первым байтам соли ячейки; `keySrc = мастер-ключ`. Сначала пробуется первая ячейка, при неудаче — вторая.
5. Версия 1.8: ключ шифра = `HMAC-SHA256(ключ HMAC = соль, данные = keySrc)`; ключ проверки = `HMAC-SHA512(ключ HMAC = соль, данные = keySrc)`, 64 байта.
6. Версия 1.8: HMAC считается по всему, что идёт после открытого заголовка и до самого HMAC (блок восстановления, соль, IV, шифртекст), и проверяется до расшифровки.
7. Версии до 1.8: шифр и HMAC используют `keySrc` напрямую, HMAC считается по расшифрованным данным; в версии 1.0 HMAC лежит внутри шифртекста. Точные ветки — строки 596–716.

### 1.4. Зашифрованное содержимое

Внутренний заголовок (26 байт): Magic (4, то же значение), HeaderSize (2), Flags (4), NumOfVariableParam (1), NumOfFields (1), NumOfEntries (4), CompressionAlgo (1; 1 — Deflate), CompressionLevel (1), UncompressedSize (4), CompressedSize (4).

Дальше идёт поток данных; если включено сжатие — это поток zlib. Особенность записи: `CompressedSize` включает 26 байт заголовка (строки 1169–1193).

Поток данных:

1. Общие параметры базы, `NumOfVariableParam` штук: идентификатор (4 байта, совпадает с битом флага) и поле. Флаги: 1 — имя пользователя по умолчанию, 2 — формат паролей, 4 — срок действия паролей в днях, 8 — размер истории по умолчанию, 16 — срок действия мастер-пароля, 32 — описание.
2. Названия полей, `NumOfFields` строк: `Title`, `UserName`, `Password`, `URL`, `Keyword`, `Notes`, `KeyValueList`, `Tags`, `CreationTime`, `ModificationTime`, `PasswChangeTime`, `PasswExpiryDate`, `PasswHistory`. Сравнение без учёта регистра; незнакомые поля пропускаются.
3. Записи, `NumOfEntries` штук: последовательность «номер поля (1 байт), поле», конец записи — байт `0xFF`.

Поле — это длина (4 байта) и данные. Строки хранятся в UTF-8 без завершающего нуля. Пустые строковые поля записи не пишутся.

| Поле | Данные |
|---|---|
| Время создания, изменения, смены пароля | `FILETIME`, 8 байт. Оригинал записывает местное время (`GetLocalTime`), а не UTC — порт делает так же |
| Срок действия | 4 байта: `(год << 16) | (месяц << 8) | день` |
| Список «ключ–значение» | одна строка: пары `ключ=значение`, разделённые `\n` |
| Теги | одна строка: теги в порядке `std::set`, разделённые `\n`. Порядок необычный (`SecureMem.h:658`): сначала по размеру буфера строки, при равном размере — побайтовое сравнение UTF-16LE. Для совпадения файлов порт сортирует так же; размер буфера нужно уточнить на эталоне |
| История паролей | без общего префикса длины: заголовок 7 байт (BlockSize 4, Flags 1, HistorySize 1, MaxHistorySize 1), затем для каждого элемента `FILETIME` (8 байт) и строка с длиной |

Особенность `BlockSize` в истории: при записи считается как `7 + сумма(8 + 4 + длина пароля в символах UTF-16)`, а не в байтах UTF-8, поэтому для не-ASCII паролей значение неверное. При чтении оно не используется. Порт пишет его так же, чтобы файлы совпадали.

Выравнивание: для AES данные дополняются случайными байтами до кратности 16; стандартного дополнения нет, длины берутся из заголовка.

Пароли записей в памяти шифруются ChaCha20 со случайным ключом сеанса (строки 1419–1478) — на формат файла это не влияет.

## 2. Зашифрованный текст

Код: `upstream/src/crypto/CryptText.cpp`; вызов — `upstream/src/main/Main.cpp:1511`.

Результат — base64 со строками по 76 символов. Внутри (текущая версия формата — 3):

```
IV, 16 байт
AES-256-CBC(
  заголовок, 8 байт: 'P' 'W' 'G', версия (1 байт), длина текста в UTF-8 (4 байта)
  текст в UTF-8, сжатый LZO1X-1
  HMAC-SHA256, 32 байта — по заголовку и сжатым данным
  случайное дополнение до кратности 16
)
```

- Ключ: `PBKDF2-HMAC-SHA256(пароль, соль = IV, 8192 итерации)`; тот же ключ используется для HMAC.
- Пароль передаётся как байты UTF-16LE.
- Младшие 4 бита 16-го байта IV хранят длину «заголовок + сжатые данные + HMAC» (до дополнения) по модулю 16. Байт меняется до вывода ключа, то есть в соль идёт уже изменённый IV.
- Версии 1–2: HMAC не зашифрован, лежит после шифртекста и считается по расшифрованным данным.
- Версия 0: ключ — 8192 раунда `SHA-256(ключ || пароль)`, где начальный ключ — 16 байт IV и 16 нулей; HMAC 16 байт по IV и шифртексту; заголовок 4 байта (только длина текста).
- Как оригинал подбирает версию при расшифровке (`Main.cpp:1538–1567`): обычно — одна попытка, она подходит для заголовков версий 1–3. С флажком «PWGen <2.3.0» пробуются версии 0, 1, 2 по очереди; для 0 и 1 пароль переводится в однобайтовую кодировку системы (`CP_ACP`: Windows-1252 на западных системах, Windows-1251 на русских). Порту нужен выбор этой кодировки — по умолчанию по языку системы.
- Ветки разбора — строки 220–330 `CryptText.cpp`.
- Предел размера текста — 128 МБ.

## 3. Ключевой файл

Код: `PasswDatabase.cpp:1698–1795`.

- Ровно 32 байта — используются как есть.
- Ровно 64 байта и все символы шестнадцатеричные — преобразуются в 32 байта.
- Иначе — SHA-256 от содержимого файла.
- Создаваемый файл: 64 шестнадцатеричных символа в верхнем регистре, без перевода строки.

## 4. Файл триграмм

Описание: `upstream/src/passw/PasswGen.h:234–246`.

| Байты | Содержимое |
|---|---|
| 1–4 | общее число триграмм (32 бита) |
| 5–12 | энтропия на символ (`double`), допустимо 1,0 < значение < log2(26) |
| 13–70316 | частоты всех 17 576 триграмм, по 4 байта |

Файл принимается, только если размер ровно 70 316 байт и сумма частот равна числу из первых 4 байт. Встроенная таблица (`PhoneticTrigram.h`): сумма 715 988, энтропия 3,6137418176108 бита на символ.

## 5. Детерминированный генератор `AESCtrPRNG`

Код: `upstream/src/random/AESCtrPRNG.cpp`.

- `Seed(данные)`: ключ = SHA-256 от данных.
- `SeedWithKey(ключ, параметр)`: ключ = `PBKDF2-HMAC-SHA256(ключ, соль = параметр, 8192 итерации)`; параметр может быть пустым.
- Счётчик — 128 бит, начинается с нуля, увеличивается как число big-endian (с последнего байта).
- Выход: AES-256-ECB от счётчика, буфер 64 байта (4 блока за раз).
- После 65 536 блоков — смена ключа: два следующих блока становятся новым ключом, счётчик не сбрасывается.
- В главном окне (Tools | Deterministic Random Generator | Set up) ключ получается так же, как в MP-генераторе: `HMAC-SHA256(ключ HMAC = пароль в UTF-16LE, данные = "PWGen MP Password Generator")`, затем `SeedWithKey(этот ключ, пустой параметр)` — `Main.cpp:4215–4245`.

## 6. Получение чисел из генератора

Код: `upstream/src/random/RandomGenerator.h`.

`GetNumRange(n)` — число от 0 до n−1, метод отбрасывания:

- n ≤ 256: читается 1 байт; значения ≥ `n * (256 / n)` отбрасываются;
- n ≤ 65 536: читается 2 байта (little-endian); порог `n * (65536 / n)`;
- иначе: читается 4 байта; порог `n * (2^32 / n)`;
- результат — прочитанное значение по модулю n.

`Permute` — перестановка Фишера–Йейтса с конца массива: для `i` от `size−1` до 1 берётся `GetNumRange(i + 1)`.

Число прочитанных байт и порядок вызовов определяют результат в детерминированном режиме, поэтому в порте их менять нельзя.

## 7. MP Password Generator

Код: `upstream/src/main/MPPasswGen.cpp:286–470`.

- Ключ: `HMAC-SHA256(ключ HMAC = мастер-пароль в UTF-16LE, данные = "PWGen MP Password Generator")` — строка `MPPG_KEYGEN_SALTSTR` из `MPPasswGen.h:37`, без завершающего нуля.
- Параметр: байты строки в UTF-16LE; если включено «Add password length to parameter», дописываются три байта: `0`, младший и старший байты длины.
- Пароль: `AESCtrPRNG.SeedWithKey(ключ, параметр)`, затем для каждого символа `набор[GetNumRange(размер набора)]`.
- Шесть наборов символов — массив `MPPG_CHARSETS` (строка 61).
- Контрольная сумма пароля: первые 2 или 4 байта `SHA-256(ключ)`, как десятичное по модулю 100 или 10 000 либо как шестнадцатеричное.
- Режим Hashapass: ключ и параметр — младшие байты символов; `HMAC-SHA1(ключ, параметр)`, первые 6 байт в base64 дают 8 символов.

## 8. Пул случайных чисел

Код: `upstream/src/random/RandomPool.*`, описание схемы — в начале `RandomPool.h`.

Выход пула случаен и с оригиналом не сравнивается, но схема переносится без изменений: пул 32 байта, шифр на выбор (AES-CTR, ChaCha20, ChaCha8), смена ключа после выдачи данных, отдельный буфер для мелких запросов. Файл `randseed.dat` — 64 байта из пула; при чтении его содержимое добавляется в пул как энтропия.

## 10. Переводы

Код: `upstream/src/main/Language.cpp`.

- `.po`: `msgid`, `msgstr`, `msgctxt`; заголовок может содержать `X-PasswordTech-Manual`.
