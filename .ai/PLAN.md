# План переноса Password Tech 3.6.1 на Linux (Rust)

Обновлён: 2026-11-19. Состояние: подготовка частично сделана (этап 0), код порта не начат.

Связанные файлы:

- `PARITY.md` — опись всего, что есть в оригинале; по ней сверяется «1:1».
- `FORMATS.md` — форматы файлов и алгоритмы, которые обязаны совпадать бит-в-бит.
- `reference/forms/*.txt` — все 21 форма оригинала в текстовом виде (координаты, подписи, меню).
- `reference/forms-outline.txt` — краткая сводка тех же форм.
- `tools/dfm2txt.py`, `tools/dfm_outline.py` — конвертеры форм.

## 1. Цель

Программа для Linux на Rust, которая повторяет Password Tech 3.6.1 настолько точно, насколько это позволяет система. «1:1» в этом плане означает:

1. Те же функции, окна, меню, сочетания клавиш, тексты и переводы.
2. То же расположение элементов в окнах — геометрия берётся из форм оригинала, а не рисуется заново.
3. Те же алгоритмы: при одинаковых входных данных (детерминированный генератор, MP-генератор) результат совпадает с Windows-версией символ в символ.
4. Совместимость файлов в обе стороны: файлы оригинала открываются в порте, файлы порта — в оригинале.
5. Отклонения допускаются только там, где Linux или Wayland не дают сделать так же. Все они перечислены в разделе 7.

## 3. Как обеспечивается 1:1

1. **Перенос по модулям.** Каждому файлу оригинала соответствует модуль Rust с тем же названием. Логика переносится построчно, порядок обращений к генератору случайных чисел сохраняется — иначе детерминированные режимы разойдутся.
2. **Опись.** Каждая функция оригинала — строка в `PARITY.md`. Этап закрыт, когда его строки отмечены и проверены.
3. **Эталоны.** Файлы и результаты снимаются с оригинала под Wine и кладутся в `fixtures/`; тесты порта сравнивают с ними.
4. **Формы не перерисовываются вручную.** Порт загружает описания форм оригинала и строит по ним окна (см. этап 5).
5. **Сторонний C-код.** Заменяется крейтом Rust, только если результат идентичен. Если нет — подключается оригинальный C-код через FFI.
6. **Тексты.** Строки интерфейса берутся из `languages/English.pot` без изменений (680 строк), поэтому 13 существующих переводов работают как есть.

## 4. Архитектура

```
PwTech-liunx/
  upstream/           оригинал v3.6.1, только для чтения
  .ai/                план, опись, справочные материалы
  Cargo.toml          workspace
  crates/
    pwtech-core/      всё, что не зависит от интерфейса
    pwtech/           исполняемый файл: GUI и консольный режим
  assets/             значки, формы, словари, переводы, common_passwords.txt
  fixtures/           эталоны, снятые с оригинала
```

Исполняемый файл один, как в оригинале: без аргументов открывает окно, с `--gen` печатает пароли в консоль. Консольный режим не должен требовать графической среды.

## 5. Решения

### 5.1. Принято по умолчанию

- Эталон — версия 3.6.1. Более новые версии оригинала в этот план не входят.
- Один исполняемый файл `pwtech`, ядро отдельной библиотекой.
- Имя файла настроек остаётся `PwTech.ini`, расширения и форматы файлов не меняются.
- Каталог данных: `~/.config/pwtech/`. Если рядом с исполняемым файлом лежит `PwTech.ini` без `UseAppDataPath=1`, используется он — как в оригинале.
- В комплект входят все 13 переводов из `upstream/languages/`, а не только немецкий, как в установщике оригинала.

### 5.2. Решено с владельцем проекта (2026-11-19)

1. **Интерфейс — GTK4** через `gtk4-rs`, без `libadwaita` (чтобы окна выглядели как обычная настольная программа, а не приложение GNOME). Пакет `libgtk-4-dev` 4.22.4 установлен.
2. **Ключ донора убран полностью.** В оригинале это код, который автор высылает сделавшим пожертвование: он убирает напоминание о пожертвовании при запуске (показывается после каждого обновления и случайно примерно в 1 из 15 запусков), добавляет отметку «DONOR» в окне About и открывает выбор другого значка программы. На работу программы он не влияет. В порте:
   - нет пункта «Enter Donor Key», напоминания и отметки в About;
   - выбор значка программы доступен всем;
   - ключ `DonorKey` в `PwTech.ini`, скопированном из Windows, игнорируется.
3. **Обновления проверяются в GitHub-репозитории порта**, а не на сайте автора оригинала:
   - запрос `https://api.github.com/repos/<владелец>/<репозиторий>/releases/latest`, тег выпуска сравнивается с версией порта;
   - расписание как в оригинале: ежедневно, еженедельно (по умолчанию), ежемесячно, выключено;
   - порт сам не обновляется, а показывает сообщение со ссылкой на страницу выпуска;
   - адрес репозитория задаётся одной константой; заполнить, когда репозиторий будет создан.
4. **Ссылки:** «Visit Website» и «Get Translations» ведут в репозиторий порта. «Donate...» остаётся и ведёт на страницу пожертвований автора оригинала — в знак авторства; если не нужен, пункт убирается.
5. **Версии:** у порта своя нумерация (теги выпусков вида `v0.1.0`). Проверка совместимости файлов перевода по-прежнему сравнивает их с версией оригинала 3.6.1. В окне About сохраняется авторство Christian Thöing и добавляется строка о порте — этого требует GPL.

## 7. Что не получится сделать так же

| В оригинале | В порте | Почему |
|---|---|---|
| «Always on Top» | в KDE — через KWin (`keepAbove` для окон программы, скрипт через D-Bus); без KWin пункт становится неактивным | Wayland не даёт окну самому управлять своим положением поверх других |
| Запоминание положения окон | запоминаются только размеры; «Reset All Window Positions» работает через KWin | Wayland не сообщает и не принимает координаты окон |
| Автонабор через `SendInput` | через портал; при первом использовании система спросит разрешение | на Wayland нет прямого ввода в чужие окна |
| Глобальные сочетания клавиш через `RegisterHotKey` | через портал; сочетания подтверждаются в системном диалоге KDE | то же ограничение |
| Сворачивание в трей, блокировка базы при сворачивании | о сворачивании сообщает KWin (скрипт через D-Bus); в других окружениях Wayland не срабатывает | Wayland не сообщает приложению о сворачивании |
| Сбор энтропии из десятков вызовов WinAPI | системный генератор, таймеры, ввод пользователя | вызовов WinAPI нет; счётчик энтропии и схема пула те же |
| `VirtualLock` | `mlock` и запрет дампа памяти | аналог |
| Стили VCL (`GUIStyle`) | светлая и тёмная темы | стилей VCL нет |
| Автозапуск через реестр | файл в `~/.config/autostart` | аналог |
| Переключатели командной строки с `/` | только `-` и `--` | `/` в Linux — начало пути к файлу |
| `PwTech.com` (обёртка для консоли) | не нужна | в Linux вывод в консоль работает и так |
| Установщик Inno Setup | `.deb`, AppImage | — |
| Шрифт Tahoma | системный шрифт | Tahoma в Linux нет; размеры подписей могут слегка отличаться |
| Перевод строки по умолчанию CRLF | по умолчанию LF, настройка та же | принято в Linux |
| Ключ донора, напоминание о пожертвовании | убраны; выбор значка программы доступен всем | решение владельца проекта (5.2) |
| Проверка обновлений на сайте автора | GitHub Releases репозитория порта | порт выпускается отдельно от оригинала (5.2) |
| `EntropyManager::AddEvent` работает с копией пула (события не попадают в пул) | события добавляются в настоящий пул | ошибка оригинала, исправлена |
| Оценка стойкости пароля с символами вне BMP: цикл по числу UTF-16-единиц читает неинициализированную память за концом строки | повторено, но за концом строки читаются нули (результат детерминирован; совпадает с оригиналом, пока читается только терминатор) | в оригинале неопределённое поведение |
| Генерация с длиной 0/отрицательной в консольной обвязке оригинала выдаёт мусор из памяти или падает | пустой результат | неопределённое поведение оригинала; из интерфейса недостижимо |
| Последние биты значений zxcvbn (1 ULP) | могут отличаться | разные библиотеки `log()` (glibc и Windows) |
| «Install language» запоминает путь к исходному файлу (а «Remove» потом удаляет исходник) | запоминается копия в папке данных | ошибка оригинала, исправлена |
| Расшифрованный текст кладётся в обычный буфер обмена | с пометкой «пароль» для Klipper (без автоочистки) | чтобы расшифровка не оседала в истории буфера |
| Сохранение базы поверх файла | запись во временный файл и атомарная замена, блокировка файла (`flock`) | защита от порчи базы при сбое |
| Заметки записей с CRLF | в окне LF, в файле CRLF, как в оригинале | GTK работает с LF |
| Второй запуск: предупреждение «An instance … is already running» и выход | второй запуск показывает окно уже работающей копии (D-Bus имя приложения); консольный режим `--gen` работает и при открытом окне | так принято в Linux |
| Поиск в базе по заголовку активного окна (горячая клавиша) | заголовок берётся у KWin (короткий скрипт через D-Bus `org.kde.KWin /Scripting`); в других окружениях — сообщение о недоступности | Wayland не сообщает заголовок чужого окна приложениям |
| Visit Website, Get Translations — сайт автора | репозиторий порта | то же |

## 9. Риски

1. **Автонабор и глобальные клавиши на Wayland.** Самое ненадёжное место. До начала этапа 8 делается прототип на KDE; если портал не подходит, останется вариант только для сеанса X11, и это будет записано в раздел 7.
2. **Совпадение детерминированных режимов.** Требует построчного переноса и одинакового порядка обращений к генератору; ошибки ловятся эталонами из пункта 5 раздела 8, поэтому эталоны нужны до этапа 2.
3. **Эталоны требуют ручной работы в окне оригинала.** Если Wine не запустит оригинал, понадобится машина с Windows.
4. **Геометрия форм.** Шрифты в Linux другой ширины; возможна подгонка масштаба. Перерисовывать формы вручную при этом не нужно.
5. **Секреты в памяти элементов интерфейса.** В оригинале та же проблема, решается чтением в защищённый буфер и затиранием; в GTK4 нужно проверить, как это сделать для полей ввода.
6. **Объём.** Около 30 тыс. строк оригинала. Работа идёт этапами, после этапа 4 уже есть полезный результат (консольный генератор и библиотека для работы с базой).
